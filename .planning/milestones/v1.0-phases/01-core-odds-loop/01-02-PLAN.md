<objective>
Wire the full off-main-thread streaming pipeline end to end: Deal → worker → throttled progress snapshots → store → live trial counter and percentages on screen.

Purpose: This is the slice that makes "watch it converge" a real mechanism rather than a UI aspiration. It proves the worker boundary, the streaming protocol, generation-tagged cancellation, and UI responsiveness INDEPENDENTLY of evaluator correctness — so that when plan 01-03 swaps in the real poker math, any bug is unambiguously a math bug, not a plumbing bug.
Output: A visibly climbing trial counter and live-updating percentages, computed in a Web Worker, backed by a deliberately stubbed trial loop that plan 01-03 replaces.
</objective>

**As a** poker learner, **I want to** deal a random Hold'em hand and watch accurate win/tie/lose and hand-category odds converge live off the main thread, **so that** probability becomes something I can see being computed rather than a static number I have to trust.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SC | Tampering | dependency integrity | mitigate | No new installs in this plan; `package-lock.json` from plan 01-01 governs. Any unplanned `npm install` here re-opens plan 01-01's legitimacy gate. |
| T-02-01 | Tampering | worker → main-thread snapshot handling (`simulationService.startSimulation`) | mitigate | Generation-tagged `requestId` on every snapshot, enforced on BOTH sides: the worker aborts when `requestId !== currentRequestId`, and the main thread drops non-matching snapshots before they reach `oddsStore`. | T-02-04 | Information disclosure | worker message payloads | accept | Payloads are integers and public card identifiers; no PII, no secrets, no network egress. Nothing to disclose. |
| T-02-S / T-02-R / T-02-E | Spoofing / Repudiation / Elevation | — | accept | No identity, no audit surface, no privilege model. Worker runs in the same browser sandbox origin as the page. |
