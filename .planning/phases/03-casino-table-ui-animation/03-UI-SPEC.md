# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope framing (locked by ROADMAP.md + 03-CONTEXT.md + 03-RESEARCH.md):** Phase 3 re-skins the already-correct, already-tested Phase 1-2 interaction loop with a full casino-table scene — felt oval, seated opponents, detailed card art, and Motion-driven deal/flip/reveal choreography — while structurally guaranteeing odds never contradict a card still mid-animation (TBL-04). ## Animation Choreography Contract

Library: `motion` (13.1.1), per D-08. All values below are locked defaults within D-08's stated bounds (~250-350ms deal duration, ~60-100ms stagger).

| Choreography | Trigger | Duration | Stagger | Easing | Notes |
|---|---|---|---|---|---|
| Deal fly-in | New hand dealt | 300ms | 80ms between cards | `easeOut` | 8 hole cards total, dealer-rotation order (A3): Opp-0, Opp-1, Opp-2, Hero ×2 rounds. Community cards are NOT part of this choreography. |
| Street-advance enter | Advance to Flop/Turn/River | 300ms | 80ms (only matters for Flop's 3 simultaneous cards; Turn/River are single cards) | `easeOut` | Cards originate from `deck-origin` and land in their community slot. Only the newly-visible card(s) animate — already-visible board cards are untouched. |
| Reveal flip | Opponent seat clicked | 400ms | n/a (both of that opponent's 2 cards flip together, no stagger) | `easeInOut` | 3D flip via `rotateY: 0 → 180deg`; parent needs `perspective: 1000px`, flipping element needs `transform-style: preserve-3d`; both faces need `backfaceVisibility: hidden`. Box dimensions do not change (see Card Dimensions). |
| Rewind exit | Rewind to earlier street | 150ms | 80ms if multiple cards leave at once | `easeIn` | Departing board card(s): opacity `1 → 0` + `translateY: 0 → 8px`. This is a real exit transition — NOT an instant unmount. |
| Re-deal cancellation | Re-deal while a previous choreography is still running | instant (0ms) | n/a | n/a | Old card elements unmount WITHOUT an exit transition (no fade/slide) — this is deliberately different from Rewind's exit. Key every card by `${seat}-${slotIndex}-${dealNonce}` so a re-deal always fully unmounts/remounts rather than Motion retargeting an existing element's animation (the anti-pattern RESEARCH flags: a re-deal must never look like one card morphing into another mid-air). |

**Reduced motion (D-09):** wrap the app in `<MotionConfig reducedMotion="user">`. When `prefers-reduced-motion: reduce` is active, every duration above becomes effectively 0 — cards appear/flip/exit directly in their final state. The `pendingAnimationCount` gate (below) still increments then resolves to 0 immediately, so TBL-04's gating remains structurally intact even with zero-duration animations; no separate reduced-motion code path is needed for the gate itself.

**Animation-gate contract (TBL-04, D-11/D-12):**
- A single numeric `pendingAnimationCount` (not a boolean) increments by 1 per card entering/exiting/flipping and decrements per that card's `onAnimationComplete`.
- **Both** branches of the odds effect — the settled-cache hit AND the live-simulation start — are gated on `pendingAnimationCount === 0`. The cache-hit branch is the one most likely to be missed (RESEARCH Pitfall 1) — it must be gated too, not just the live-simulation branch.
- The instant any qualifying action fires (deal / advance / rewind / reveal), the `OddsPanel` switches to its pending visual state (A9: em dashes, `opacity: 0.6`, `aria-busy="true"`) — this happens synchronously with the action, not only once the gate gets checked, so no stale number is ever visible even for one frame.
- No odds number may change while any card is mid-flight, and no odds number may reflect a card the user cannot yet see (the literal TBL-04 acceptance bar).

## Accessibility Contract

Carries forward every rule from Phase 2's Accessibility Contract (native `<button>`s, `<dialog>` focus trap, visible `:focus-visible`, native `disabled` semantics, `aria-label`s on opponent seats, `role="alert"` on the error banner). New rules for this phase:

- **Card image `alt` text — split by context, to avoid double-announcement:**
  - Inside `hero-hole` and `board-cards` (no wrapping `aria-label` on these containers): `<PlayingCard>`'s `alt` is a human-readable string, `"{Rank} of {Suit}"` (e.g. `"Ace of Spades"`), never the raw code (`"As"`) — the raw code is not meaningful to a screen-reader user.
  - Inside `opponent-seat-{i}` (which already carries a comprehensive `aria-label` describing full state): inner `<PlayingCard>`/`<CardBack>` images use `alt=""` (decorative) — the button's `aria-label` is the authoritative accessible name; duplicating it via image `alt` would cause double-announcement.
  - Standalone `<CardBack>` (e.g. the `deck-origin` stack): `alt=""` and the whole stack is `aria-hidden="true"` (purely decorative).
- **Seat-label badges** (`seat-label-hero`, `seat-label-opponent-*`) are `aria-hidden="true"` for the opponent variants (the info duplicates the opponent-seat button's own `aria-label`); the hero "You" badge is NOT `aria-hidden` since it conveys information not present elsewhere.
- **`Set Up Scenario` toggle:** exposes `aria-expanded` and `aria-controls` pointing at the `card-picker` region, per standard disclosure-pattern semantics (WAI-ARIA Disclosure).
- **Reduced motion:** `prefers-reduced-motion: reduce` must produce fully equivalent end states with zero animation — no content or functionality is ever gated behind an animation actually playing (the `pendingAnimationCount` gate resolves to 0 immediately in this mode).
- **`OddsPanel` pending state:** `aria-busy="true"` while `pendingAnimationCount > 0`, so assistive tech knows the region is mid-update rather than reporting stale/absent values as final.
