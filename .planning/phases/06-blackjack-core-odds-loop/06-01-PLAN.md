## Phase Goal

**As a** probability explorer using the simulator, **I want to** play a full Blackjack round on its own table — deal, watch bust / dealer-outcome / EV odds converge live, hit or stand, reveal the hole card, and switch the shoe between 1 and 2 decks — **so that** I can see exactly how each new piece of information and each extra deck reshapes the numbers.

<sub>Derived from ROADMAP Phase 6's `**Goal:**` line, which is written in prose rather than user-story form. No operator input was available (standing `--auto` directive); the three slots are taken directly from that goal sentence, not invented.</sub>

<objective>
Build the entire Blackjack rules engine and Monte Carlo trial loop as pure, node-testable functions, plus the wire types the worker and the stores will both consume.

Purpose: this is the only genuinely new code in Phase 6 — every other layer is a config or a copy of proven machinery. It is also where every silent-correctness bug lives (soft totals, natural pricing, the dual-exclusion-set rule, the dealer-natural comparison branch). Getting it right, with property and statistical tests, before any UI exists is what makes the rest of the phase mechanical.
Output: five engine/worker modules and four test files, all runnable under `@vitest-environment node` with no DOM, no worker, and no React.

**Planner decisions taken under Claude's Discretion (06-CONTEXT "Claude's Discretion"), recorded here for audit:**
- `blackjackProtocol.ts` is created by THIS plan rather than by the wave-2 worker plan. Two wave-2 plans (worker config and stores) consume its types independently and run in parallel worktrees, so the types must land in wave 1 or one of them cannot compile.
- Rank values are resolved through a module-scope `Map<Card, number>` built once from `ALL_CARDS` via `getRank`, not by calling `getRank` per card inside the trial loop — `getRank` validates and throws on every call, which is wasted work across ~800k calls per 200k-trial run.
- Trial-loop design fork (06-RESEARCH "Should the trial condition out a hypothetical dealer natural?"): **Option A** — no rejection sampling. Locked here so it cannot drift mid-implementation. Option B is a deferred rigor enhancement, not a bug.
</objective>
