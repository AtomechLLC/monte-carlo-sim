## Phase Goal

**As a** probability explorer using the simulator, **I want to** play a full Blackjack round on its own table — deal, watch bust / dealer-outcome / EV odds converge live, hit or stand, reveal the hole card, and switch the shoe between 1 and 2 decks — **so that** I can see exactly how each new piece of information and each extra deck reshapes the numbers.

<objective>
Build the Blackjack felt: composition root with the CR-02-safe gate release, dealer and player areas with real card presentation, the outcome banner, the symmetric restore-mount protection, and every Phase 6 CSS rule.

Purpose: this is where 05-REVIEW's two shipped Hold'em bugs (CR-02 gate-unit theft on re-mount, WR-02 choreography replay on switch-back) would recur identically for Blackjack if written from a naive first draft. Both are designed in here rather than found in review later.
Output: four components, one generalized animation primitive, and the phase's complete stylesheet delta.

**Planner decisions taken under Claude's Discretion (06-CONTEXT grants component decomposition, dealer playout pacing and EV tile styling; UI-SPEC line 189 marks component/file names non-contractual), recorded for audit:**
- **This plan owns ALL of `src/App.css` and `src/index.css` for the phase.** Plan 06-06 (odds cluster) and 06-07 (controls, game root) run in adjacent waves and emit class names but write no CSS, so the two stylesheets have exactly one owner and no same-wave conflict. The class-name contract those plans render against is listed in `<interfaces>` below and is binding in both directions.
- **Deck-origin geometry is reused, not re-derived.** `dealOriginOffset('seat-opponent-1')` serves the dealer row and `dealOriginOffset('seat-hero')` the player row; `src/ui/tableGeometry.ts` is NOT modified (that would put a shipped Hold'em module in this diff for no behavioral gain).
- **Dealer playout pacing (A12) is expressed through `AnimatedCard`'s existing `dealIndex` arithmetic**, not by adding a second timing constant. `AnimatedCard` computes `delay = 0.08 * dealIndex`, so passing `dealIndex = 5 + i * 2.5` yields a 400 ms offset (the hole flip) followed by 200 ms between successive draws — exactly A12 — with zero change to the timing constants Hold'em shares.
- **The dealer playout is resolved synchronously in the store (plan 06-04) and merely PRESENTED with a stagger here.** No timed state machine, no `setTimeout` choreography — the same predetermine-then-present discipline Hold'em already uses.
</objective>
