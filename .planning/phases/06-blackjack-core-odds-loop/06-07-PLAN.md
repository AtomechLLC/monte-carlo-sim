## Phase Goal

**As a** probability explorer using the simulator, **I want to** play a full Blackjack round on its own table — deal, watch bust / dealer-outcome / EV odds converge live, hit or stand, reveal the hole card, and switch the shoe between 1 and 2 decks — **so that** I can see exactly how each new piece of information and each extra deck reshapes the numbers.

<objective>
Wire the vertical slice together: the controls, the game root with its gated odds effect, the App fork, the placeholder's retirement, and the end-to-end loop test that proves BJ-02 through BJ-07 actually work.

Purpose: everything before this plan is a component or a store. This is the plan where a user can deal a blackjack round and watch the odds converge — the phase's whole point. It is also where the 05-REVIEW CR-01 gate-order defence and the D-02 leak guard must be re-implemented rather than inherited, because the blackjack odds effect is brand-new code.
Output: two components, a slimmer App, a retired placeholder, retargeted guards, a mirror-image testid sweep, and an end-to-end loop suite.

**Planner decisions taken under Claude's Discretion, recorded for audit:**
- **The odds-effect dependency array includes `roundNonce` even though `round` object identity already changes per deal.** A deal that resolves on a natural changes `roundPhase` too, and a re-deal into an identical-shaped state would otherwise be indistinguishable; the nonce makes each deal a distinct generation with no reliance on reference identity.
- **`App.modeSwitch.test.tsx`'s "the blackjack-scene subtree contains zero `<button>` elements" case is RETARGETED, not deleted.** That assertion encoded Phase 5's D-03 ("the placeholder has no controls"), which Phase 6 D-13 supersedes by design. It becomes an assertion that the scene now contains exactly the expected Phase 6 controls, with both decision tags cited — the guard file's standing rule (retarget, never delete) applied to a behavioral suite.
</objective>
