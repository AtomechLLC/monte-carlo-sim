# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope framing (locked by 06-CONTEXT.md D-13/D-14 + 06-RESEARCH.md + BJ-02..BJ-07):** Phase 6 replaces the Phase 5 Blackjack placeholder with the full Blackjack table: dealer area top-center (upcard face-up + hole face-down as a `FlipCard`), player hand bottom-center, Deal/Hit/Stand controls + a blackjack-local 1/2-deck toggle in the control bar, an outcome banner on resolution, and a Blackjack odds cluster docked OUTSIDE the felt (Phase 3 precedent) whose educational centerpiece is the 7-bucket dealer final-outcome distribution. This document extends `03-UI-SPEC.md` and `05-UI-SPEC.md`: every token, testid, and copy string from those contracts not explicitly amended here carries forward unchanged. **Hold'em is not restyled — zero Hold'em testids, styles, or copy change this phase.** The Phase 5 DOM-absence contract still applies in both directions: no Hold'em testid in Blackjack mode, and no `blackjack-*` testid in Hold'em mode.

**Autonomous mode note:** Generated inside an unattended `--auto` chain. No question was asked interactively — every gray area was resolved with the recommended default and is logged in "Defaults Chosen" below for audit.

| A2 | Is Deal disabled mid-round (during `player-turn`)? | **Never disabled.** Clicking Deal mid-round silently abandons the current round and deals a new one — same silent-cancellation precedent as Phase 3's re-deal-during-animation (D-10 of 03-CONTEXT). ## Animation Choreography Contract

Library: `motion` (13.1.1). Reuses `AnimatedCard`/`FlipCard`/`useAnimationGate` and Phase 3's duration family. All cards keyed by `${role}-${slotIndex}-${roundNonce}` (A2) so a re-deal always unmounts/remounts instantly, never retargets mid-air.

| Choreography | Trigger | Duration | Stagger/Pacing | Easing | Notes |
|---|---|---|---|---|---|
| Deal fly-in | Deal clicked | 300ms/card | 80ms | `easeOut` | 4 cards from `blackjack-deck-origin`, casino order: player 1 → dealer upcard → player 2 → dealer hole. The hole LANDS face-down (FlipCard back face). |
| Hit fly-in | Hit clicked | 300ms | n/a (single card) | `easeOut` | Deck → next player slot. The centered row may shift by a half-card width as it recenters — smooth via Motion layout animation; instant under reduced motion. |
| Hole reveal flip | `blackjack-hole-reveal` clicked (early reveal, BJ-06) OR automatically as part of Stand/natural resolution | 400ms | n/a | `easeInOut` | Identical 3D `rotateY` spec as the opponent reveal flip (perspective 1000px, preserve-3d, backface hidden). One-way per round. |
| Dealer playout | Stand clicked | Flip 400ms, then 300ms per draw | 200ms between successive draws (A12) | `easeOut` | Hole flips FIRST, then draws append left-to-right. The running dealer total badge updates as each card lands. |
| Outcome banner enter | `roundPhase === 'resolved'` AND `pendingAnimationCount === 0` | 150ms | n/a | `easeOut` | Fade + 4px rise. The banner must NEVER appear while any card is in flight. |
| Re-deal cancellation | Deal during any in-flight choreography or mid-round | instant (0ms) | n/a | n/a | Old cards unmount with no exit transition (carried Phase 3 rule). |

**Reduced motion (carried):** app-wide `<MotionConfig reducedMotion="user">` already covers every new choreography — all durations collapse to 0, end states identical, and the gate still increments/resolves so TBL-04 stays structurally intact.

**Animation-gate contract (TBL-04 — carried verbatim, applied to Blackjack):**
- Every `blackjackStore` action that moves cards (`deal`, `hit`, `stand`, `reveal`) calls `beginAnimation()` synchronously in the same tick; the Blackjack composition root releases via the CR-02-safe prevRef-gated effect (06-RESEARCH Pattern 3). Odds never move while cards fly.
- The instant any such action fires, `blackjack-odds-panel` switches synchronously to its pending state: em dash `"—"` in every stat cell and the trial counter, `opacity: 0.6`, `aria-busy="true"` — identical to Hold'em's A9 state, via the same `pendingAnimationCount` gate.
- **Deck toggle is NOT a card animation:** no gate involvement. Instead the blackjack odds store resets synchronously on toggle (counter 0, stats `"—"` via the zero-trials path of `formatPct`/`formatEv`), then the restarted run streams (A3). This is the BJ-07 findability moment: click → every number blanks in the same frame → the trial counter restarts from 0 and climbs → the numbers settle on visibly different values (most legibly the Natural and Bust rows of the dealer table). The `{N}-deck shoe` subtitle on the dealer table (below) updates in the same frame, tying the new numbers to the new shoe.

## Accessibility Contract

Carries forward every rule from Phases 3/5 (native `<button>`s, visible `:focus-visible`, native `disabled`, card `alt` rules, reduced motion, `aria-busy`, DOM-absence as an accessibility property). New/applied rules:

- **Card `alt` text (carried split-by-context rule):** player cards, the dealer upcard, and dealer playout draws sit in unlabeled containers → `alt="{Rank} of {Suit}"` (human-readable, never raw codes). The hole FlipCard sits inside `blackjack-hole-reveal`, which carries the authoritative `aria-label` → inner faces use `alt=""` (no double-announcement — opponent-seat precedent). `blackjack-deck-origin` is `aria-hidden="true"` with `alt=""` backs.
- **Badges:** `blackjack-dealer-label` and `blackjack-player-label` are NOT `aria-hidden` — the "Dealer"/"You" context and live totals (A11) are information not duplicated elsewhere (the reveal button's label covers only the hole card).
- **Deck toggle:** `role="group"` + `aria-label="Deck count"`, `aria-pressed` per segment, active segment never disabled (operable-toggle rule, Phase 5 A5 precedent). The A3 duplicate-guard disable uses native `disabled` + `title` explanation.
- **Outcome banner:** `role="status"` (polite live announcement of the round result) — NOT `role="alert"`, which stays reserved for error banners.
- **`blackjack-odds-panel`:** `aria-busy="true"` while the animation gate is pending — identical semantics and timing to Hold'em's panel.
- **Dealer table:** a real `<table>` with `<caption>` (caption + subtitle pattern), `<th scope="row">` bucket labels — mirroring `category-table`'s shipped structure.
- **No forced focus movement** on Deal/Hit/Stand/reveal/toggle — the clicked control keeps focus (Phase 5 precedent). When the reveal button becomes `disabled` post-click, focus loss to `<body>` is acceptable and matches the shipped opponent-seat reveal behavior.
- **Reduced motion:** all Phase 6 choreography (deal, hit, flip, playout, banner enter) collapses to instant end states under `prefers-reduced-motion: reduce`; the gate still cycles so no functionality is ever gated behind an animation actually playing.
