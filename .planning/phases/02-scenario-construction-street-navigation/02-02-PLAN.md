## Phase Goal

**As a** poker learner exploring how information changes the odds, **I want to** deal a hand and walk it street by street — forward and back — **so that** I can watch the win, tie and hand-category probabilities recompute against exactly the cards I can currently see.

<objective>
Complete the street-navigation vertical slice: `Deal` now fixes the entire runout up front (D-01), Advance/Rewind move a visible-street pointer over it, the board renders the cards for the current street, and the odds effect recomputes on every knowledge change with proper cleanup and visible error handling.

Purpose: This is the first plan a user can see. It turns 02-01's conditioning contract into the interaction loop NAV-01 describes, and closes D-14's WR-01 (main-thread side) and WR-02.

Output: A `gameStore` holding the predetermined runout and street pointer, `StreetControls` and `BoardDisplay` components, a rewired `App` effect watching `[runout, street, revealedMask, dealNonce]` with ignore-flag cleanup, and a `simulation-error` banner.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User click → Zustand store | Only enumerated actions (`deal`, `advanceStreet`, `rewindStreet`); no free-text or numeric input crosses this boundary. |
| Store/effect → Web Worker | `ConditionedState` built by `deriveConditionedState` only. |
| Worker error → UI | Error message string rendered as text content. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07 | Information disclosure | `App` effect building simulation inputs | mitigate | The effect calls `deriveConditionedState(runout, street, revealedMask)` and never reads `runout.board`/`runout.opponentHoles` itself; an integration test asserts hidden cards remain in `remainingDeck`. |
| T-02-08 | Denial of service | Concurrent worker loops from rapid Advance/Rewind | mitigate | Ignore-flag cleanup plus `cancelSimulation()` on every effect teardown, dependency array covering all four triggers. |
| T-02-09 | Tampering | Worker error message rendered into the DOM | accept | React escapes text children by default and the string originates from a same-origin `Error.message`; no `dangerouslySetInnerHTML` is introduced. |
| T-02-10 | Spoofing | — | accept | No identity, no authentication surface. |
| T-02-SC | Tampering | npm installs | accept | No packages added; if an install appears necessary, stop and escalate. |
