    Create `src/engine/cards.ts` exporting `FULL_DECK` (a re-export of `ALL_CARDS` from `@poker-apprentice/types`, typed `readonly Card[]`), the constants `OPPONENT_COUNT = 3` and `CARDS_PER_TRIAL = 11`, and `deckWithout(excluded: readonly Card[]): Card[]` which returns `FULL_DECK` filtered to exclude every card in `excluded`.     Create `src/engine/rng.ts` wrapping `pure-rand@8.4.2`. Critical import constraint: `pure-rand@8.4.2` has NO top-level `"."` export, so every import must use a subpath — `xoroshiro128plus` from `pure-rand/generator/xoroshiro128plus` and `uniformInt` from `pure-rand/distribution/uniformInt`. A bare `import { xoroshiro128plus } from 'pure-rand'` throws `ERR_PACKAGE_PATH_NOT_EXPORTED`. Export three things: `createRng(seed?: number)` returning a `xoroshiro128plus` generator seeded from the argument or from a time-plus-entropy default; `drawN(rng, pool, n)` implementing a partial Fisher-Yates over a fresh copy of `pool` (swap position `i` with `uniformInt(rng, i, working.length - 1)` for `i` in `[0, n)`, then return the first `n` entries); and `createDrawer(rng, pool, n)` which allocates ONE working array up front and returns a closure performing the same partial Fisher-Yates on that reused array, returning a fresh `n`-length slice each call. `createDrawer` exists for the hot trial loop in plan 01-03 — repeated partial shuffles of an already-permuted array remain uniform, and reusing the buffer avoids per-trial GC pressure. Never implement shuffling as `array.sort(() => Math.random() - 0.5)`; that is a documented non-uniform shuffle and is not seedable.

    Create `src/state/gameStore.ts` as a Zustand store using the `create<GameState>()((set, get) => ({ ... }))` pattern. State: `heroHole: [Card, Card] | null` initialised to `null`, and `dealNonce: number` initialised to `0`. Action `deal()` creates a fresh RNG via `createRng()`, draws 2 cards with `drawN(rng, FULL_DECK, 2)`, and sets `heroHole` to that pair while setting `dealNonce` to the previous value plus 1. `dealNonce` is deliberately a single counter that serves as both the re-deal trigger and, in plan 01-02, the worker `requestId` — do not introduce a second counter.
