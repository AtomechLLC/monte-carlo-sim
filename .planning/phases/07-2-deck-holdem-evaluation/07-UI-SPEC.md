# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope framing (locked by 07-CONTEXT.md D-01..D-16 + 07-RESEARCH.md + HE2-01..03):** Phase 7's UI surface is small and surgical — a Hold'em-local deck toggle in the control bar (D-01, mirroring blackjack's Phase 6 A4 segmented control verbatim), a corner copy-cue badge on the second visible copy of any duplicated card on the felt (D-08/HE2-03), a Five of a Kind row appended at the strength end of the category table in 2-deck mode only (D-05/D-09 amended), and count-aware presentation in the CardPicker (D-07/D-15). This document extends `03-UI-SPEC.md`, `05-UI-SPEC.md`, and `06-UI-SPEC.md`: every token, testid, and copy string from those contracts not explicitly amended here carries forward unchanged. **Two hard isolation rules govern everything below:** (1) zero blackjack surface changes — no `blackjack-*` testid, copy string, style, or file is touched this phase (D-11); (2) Hold'em's shipped 1-deck DOM is not amended — no shipped string, testid, or layout changes; everything new is additive, and every 2-deck-only element is DOM-absent at `deckCount === 1`.

**Autonomous mode note:** Generated inside an unattended `--auto` chain. No question was asked interactively — every gray area was resolved with the recommended default and is logged in "Defaults Chosen" below for audit.

## Copy Cue (D-08, HE2-03)

A small corner badge on the **second visible copy** of any duplicated card on the felt — hero holes, board, and revealed opponent holes. Renders ONLY at `deckCount === 2`; at 1 deck the badge, its class, and its testid are DOM-absent (duplicates are impossible there anyway).

**Visual treatment (A5/A6):**

```css
/* 2-deck only; the shipped .card-slot rules are untouched */
.card-slot--cued { position: relative; }

.copy-cue {
  position: absolute;
  top: 4px;                       /* xs */
  right: 4px;                     /* xs — top-right: the empty corner on the card faces */
  padding: 0 4px;                 /* xs */
  font-size: 14px;                /* Label size */
  font-weight: 600;               /* existing semibold */
  line-height: 1.4;               /* Label line-height */
  background: var(--felt-dark);   /* solid felt token — AA on white card faces (A6) */
  color: var(--seat-badge-text);
  border-radius: 12px;            /* badge-radius precedent */
  pointer-events: none;
}
```

Visible content: the two characters `×2` (multiplication sign + "2"). No icon asset, no exclamation mark, no destructive color — the cue must read as "two physical copies of this card are in play," a deliberate table fact, never an error state.

**Placement & riding (binding):**
- The badge renders INSIDE the card's animation wrapper — as the last sibling of the `PlayingCard` inside `AnimatedCard` (hero/board), and inside the face-up `.flip-card-face` for revealed opponent holes (so `backface-visibility` hides it correctly mid-flip). It therefore rides every fly-in, flip, rewind-exit, and the restore-mount path automatically (D-08: "badge rides the card, not the slot").
- No independent animation, no gate involvement (A7): the badge mounts/unmounts instantly with the render commit. Reduced motion needs no extra path.
- **Felt keys stay positional** (`${slot}-${dealNonce}` / `animationKey` never card identity) — the cue derivation must NEVER introduce value-based React keys (07-RESEARCH §9, Pitfalls 9/14 carried).

**Second-copy determination (binding, from 07-RESEARCH §9 / Pitfall 7):** a deterministic canonical scan over currently-visible cards — hero holes in slot order, then board in street order, then revealed opponents by seat index (seat order, not reveal chronology — `revealedMask` records a set) — badging the second encounter of any value. A pure function of `(runout, street, revealedMask, deckCount)`; rewind/advance/reveal recompute it deterministically. A badge may therefore appear on an already-settled card (e.g., a revealed opponent's card gains the cue when a later street boards its twin) and disappears on rewind — it never migrates between two simultaneously-visible copies (with both copies visible, the later-in-scan card wears it, always).

**Accessibility (A11):**
- Badge markup: `<span aria-hidden="true">×2</span>` + `.visually-hidden` sibling with the copy `"Second copy — two physical copies of this card are in play"`.
- Revealed-opponent buttons additionally append `" — second copy of {card}"` to their `aria-label` per badged card at `deckCount === 2` (shipped label byte-identical at 1 deck).

**Testid:** every badge carries `data-testid="holdem-copy-cue"` (one per designated second copy; tests assert counts globally or scope via the parent container — `hero-hole`, `board-cards`, `opponent-seat-{i}`).

## CardPicker in 2-Deck Mode (D-07/D-15, DECK-04 substrate)

The picker reads Hold'em's live `deckCount` (closing WR-01 early — the pinned `const deckCount: DeckCount = 1` becomes a live read AND is passed as `setPick`'s third argument; 07-RESEARCH §7). Presentation contract:

| State (`deckCount === 2`) | Cell behavior |
|---------------------------|---------------|
| 0 copies of a value consumed | Enabled, plain `{card}` label, no title — identical to a fresh 1-deck cell. |
| 1 copy consumed (by any slot other than the open slot's own pick) | **Enabled** — the second copy is pickable. Plain `{card}` label (no visible change), `title="1 of 2 copies used"` (A9). |
| 2 copies consumed | `disabled` (shipped dimming), visible label `{card} (used)` — same suffix string as 1-deck — `title="Both copies already used in this hand"`. The third copy is structurally unpickable. |
| Open slot's own pick | Re-picking the same card into the same slot is never blocked (shipped `remainingCopies` + own-card add-back, unchanged). |

At `deckCount === 1` every label, title, disabled state, and behavior is byte-identical to shipped (`title="Already used in this hand"`).

**Deck toggle with picks present (A4, binding):**
- **1→2:** all picks retained (every value has ≥1 copy in the 104 shoe). Cells that were `(used)` re-enable in the same render (one copy now remains); their label drops the `(used)` suffix and they gain the 1-of-2 title.
- **2→1 with no duplicated picks:** all picks retained; availability recomputes — any value with 1 copy consumed becomes `(used)`/disabled.
- **2→1 with duplicated picks:** unreachable — the `"1 deck"` segment is disabled by the guard (A4) until the user clears a duplicate. **No pick is ever silently cleared by a deck toggle.**
- Picks flow into the next `deal()` via `shoeWithout(deckCount, picked)` — a pick of both copies of a value at 2 decks deals correctly (D-07's behavioral test surface).

No copy cue appears in the picker — the cue is a felt-only element (D-08); the picker communicates copy state via counts/titles above.
