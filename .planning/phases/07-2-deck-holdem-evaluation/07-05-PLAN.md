## Phase Goal

**As a** probability explorer using the simulator, **I want to** play Hold'em over a 104-card two-deck shoe — with duplicate-card hands evaluated correctly, a Five of a Kind row in the odds table, and a visible cue on the second copy of any card on the felt — **so that** I can see exactly how deck composition changes what hands are possible and how likely they are.

<objective>
Give the user the control that turns 2-deck Hold'em on, wire the deck count into the odds effect, retarget the guard that currently forbids exactly that, and write every style Phase 7 needs.

Purpose: this is the plan where 2-deck Hold'em becomes reachable. It is also the phase's single highest-risk commit-discipline moment: `App.modeShell.guard.test.ts` fails on ANY `deckCount` token in `HoldemGame.tsx` today, so the feature and its guard amendment must land together or the suite goes red — the exact same move this guard already performed for the other game in 06-07.
Output: the toggle and its two affordances, the effect wire, a retargeted guard, the phase's complete CSS, and an App-level suite pinning the D-03 cache rule and the D-02 lifecycle end to end.

**Planner decisions taken under Claude's Discretion, recorded here for audit:**
- This plan owns `src/App.css` for the WHOLE phase, including the `.copy-cue` and `.card-slot--cued` rules whose class names plan 07-04 emitted. Single CSS ownership per wave is what keeps parallel worktrees conflict-free, and it is the shipped 06-05 precedent (one plan wrote every Phase 6 rule while 06-06 and 06-07 emitted class names and wrote none).
- The A4 guard reads `hasDuplicatePick` from `pickerStore` (added in plan 07-02) rather than recounting picks in the component — one count-aware source, no second duplicate-counting loop in the UI.
- `deckCount` IS added to the odds effect's dependency array even though D-02 makes it strictly unnecessary (a mid-hand change bumps `dealNonce`; an idle change early-returns at `!runout`). It is harmless belt-and-braces and removes a reader's obligation to re-derive that argument. It is inserted BEFORE `pendingAnimationCount` because the guard pins that the array literally ends `pendingAnimationCount, mode]`.
</objective>
