## Phase Goal

**As a** probability explorer using the simulator, **I want to** play Hold'em over a 104-card two-deck shoe — with duplicate-card hands evaluated correctly, a Five of a Kind row in the odds table, and a visible cue on the second copy of any card on the felt — **so that** I can see exactly how deck composition changes what hands are possible and how likely they are.

<objective>
Put Five of a Kind on the odds table in 2-deck mode — as a real eleventh row with a live converging percentage and a working locked-in tick — while leaving the 1-deck table with zero trace of it.

Purpose: this row is the phase's visible payoff. Watching a probability that reads a flat 0.00% at one deck converge to a small nonzero value at two is what makes "deck composition changes what is possible" tangible rather than abstract. The plan also closes 07-RESEARCH Pitfall 3: `lockedInCategory` is a MAIN-THREAD evaluator call site whose visible-card input can contain duplicates at two decks, which is exactly where the stock evaluator returns garbage or throws in the UI layer.
Output: one derived constant, one deck-count-aware routing parameter, one conditional table row, and two sibling test files pinning DOM presence and absence in both directions.

**Planner decisions taken under Claude's Discretion (07-CONTEXT leaves the row-injection mechanism open), recorded here for audit:**
- The row source is an 11-entry constant DERIVED by spreading the shipped 10-entry `CATEGORY_LABELS` and appending one label. Widening `CATEGORY_LABELS` itself is not an option: `App.test.tsx` line 132 (frozen) renders at one deck and compares the rendered row labels against the whole constant, so widening it reds an untouchable file.
- The row-level testid is applied conditionally by index, so the ten shipped rows gain no attribute at all and their DOM stays byte-identical. Only the new, 2-deck-only row carries one (UI-SPEC A8).
- `lockedInCategory` takes `deckCount` as an optional fourth-position parameter defaulting to 1, following `deriveConditionedState`'s convention, so `lockedCategory.test.ts` and every other existing caller need no edit.
</objective>
