## Phase Goal

**As a** probability explorer using the simulator, **I want to** play Hold'em over a 104-card two-deck shoe — with duplicate-card hands evaluated correctly, a Five of a Kind row in the odds table, and a visible cue on the second copy of any card on the felt — **so that** I can see exactly how deck composition changes what hands are possible and how likely they are.

<sub>Derived from ROADMAP Phase 7's `**Goal:**` line, which is written in prose rather than user-story form. No operator input was available (standing `--auto` directive); the three slots are taken directly from that goal sentence and its four success criteria, not invented.</sub>

<objective>
Build the duplicate-aware evaluation layer as a pure, node-testable engine module, validated against an independently-written brute-force oracle and two seeded statistical anchors.

Purpose: this is the correctness-critical core of the whole phase and the milestone's single highest-risk item. 07-RESEARCH proved that the stock evaluator does NOT reliably crash on duplicates — it silently returns wrong answers for ~17.7% of duplicate windows and malformed `StraightFlush` objects for another ~1.6%. An under-built gate would therefore pass every smoke test while corrupting one trial in five. Everything downstream (equity hoist, worker snapshots, the Five of a Kind row) is mechanical once this module is right.
Output: one engine module plus a test-only oracle and three test files, all runnable under `@vitest-environment node` with no DOM, no worker and no React.

**Planner decisions taken under Claude's Discretion (07-CONTEXT "Claude's Discretion"), recorded here for audit:**
- Module decomposition: ONE file, `src/engine/evaluatorTwoDeck.ts`. The gate, proxy builder, flush scorer and comparator share the same module-scope lookup tables and the same stamped array; splitting them would either duplicate the tables or export hot-path internals across a module boundary for no readability gain.
- The D-13 statistical anchor lives HERE, at the evaluator level, rather than in the `runTrials` integration plan. 07-RESEARCH establishes that `categoryCounts` semantics are "hero's fixed hole + 5 board cards drawn from the 102-card conditioned pool — marginally a uniform 5-subset of 102", so drawing 5 board cards directly measures exactly the same probability with none of the integration surface in the way. Plan 07-03 adds a cheaper end-to-end assertion (11-length snapshot, index-10 tallies, sums reconcile) instead of re-paying 200k trials for the same statistic.
- Assumption A1 (07-RESEARCH) — the dup-flush multiset tiebreak, so flush `(A,A,4,3,2)` beats flush `(A,K,Q,J,9)` — ships as the working convention, pinned by explicit vectors and by the oracle. It is documented in-code as a defined convention (same treatment class as D-05's ranking flag), not as a derived truth.
</objective>

import type { Card } from '@poker-apprentice/types';

/** Extends HandStrength (0-9) upward. Index 10 is the odds table's new row. */
export const FIVE_OF_A_KIND = 10;
export type ExtendedStrength = HandStrength | 10;

export interface HandTwoDeck {
  strength: ExtendedStrength;
  /** Best-5 card list. On the proxy path this MAY contain a SYNTHETIC card (a remapped
   *  suit) — display-only, consumed by nothing today. Never feed it into physical-card
   *  accounting and never into the library comparator (Pitfall 5). */

   *  tiebreak vector as rank INDICES descending (2 -> 0 ... A -> 12). Absent means the
   *  result is stock-shaped and stock-comparable. */

}

export function evaluateHandTwoDeck(holeCards: [Card, Card], communityCards: Card[]): HandTwoDeck;
