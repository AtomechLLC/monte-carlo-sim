# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope framing (locked by ROADMAP.md + 05-CONTEXT.md):** Phase 5 delivers exactly BJ-01 — a mode switcher and an isolated Blackjack placeholder shell. It is NOT a design phase: no new gameplay, no new odds UI, no new animation. This document extends `03-UI-SPEC.md` (Phase 3's design system) with (1) the mode switcher, (2) the Blackjack placeholder screen, and (3) the DOM-absence contract for Hold'em-only elements in Blackjack mode. Every token, testid, and copy string from `03-UI-SPEC.md` not explicitly amended here carries forward unchanged.

**Autonomous mode note:** Generated inside an unattended `--auto` chain. No question below was asked interactively — every open item was resolved with the recommended default and is logged in the Autonomous Resolution Log for audit.

## Accessibility Contract

Carries forward every rule from Phase 3's Accessibility Contract unchanged (native `<button>`s, `<dialog>` focus trap, visible `:focus-visible`, native `disabled` semantics, card `alt` text rules, reduced motion, `OddsPanel` `aria-busy`). New rules for this phase:

- **Mode switcher group:** `role="group"` with `aria-label="Game mode"` on the `game-mode-switcher` wrapper; each button carries `aria-pressed="true"`/`"false"` reflecting the active mode (A4). Neither button is ever `disabled` (A5).
- **No forced focus movement on mode switch.** The clicked switcher button keeps focus naturally (default browser behavior) — no focus is programmatically moved into the newly-shown scene. Keeps keyboard users oriented without inventing new focus-management scope.
- **DOM-absence is an accessibility property, not just a test-isolation property (D-04):** a screen-reader user navigating by heading or landmark in Blackjack mode never encounters an inert/dead Hold'em control — every Hold'em element is fully removed from the DOM, not just visually hidden (`display: none` on a live, focusable Hold'em button would still be a trap if it were merely hidden rather than unmounted).
- **`blackjack-empty-state`:** plain semantic `<h2>` + `<p>`, no `role="alert"` or `aria-live` — matches the existing `empty-hand-state` precedent of a static, non-urgent placeholder.

## Animation

No new animation choreography this phase. Switching modes is an instant DOM swap (unmount one scene, mount the other) — no transition, no Motion component. The existing Phase 3 gate/cleanup contract (`pendingAnimationCount`, `useAnimationGate`/`useExitGate` unmount cleanup) already guarantees a clean drain when the Hold'em scene unmounts mid-animation (D-08); this phase adds no new animation code, only a test obligation (covered in planning/execution, not this design contract) to prove that guarantee holds across a mode switch.
