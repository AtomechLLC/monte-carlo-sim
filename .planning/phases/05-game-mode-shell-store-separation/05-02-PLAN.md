**Critical harness fact for Task 2.** `src/test/setup.ts` forces `prefers-reduced-motion: reduce` globally for every test (jsdom has no compositor). `AnimatedCard.tsx` line 38 and `FlipCard.tsx` line 37 both derive `enabled = !reduce`, so under the default harness **no real card ever calls `beginAnimation()`** — a switch-mid-deal test written against the default harness would assert a vacuous truth (the counter was 0 the whole time). The established escape hatch is `src/ui/FlipCard.test.tsx` lines 6-22: a file-scoped `vi.mock('motion/react', ...)` that spreads `importActual` and overrides `useReducedMotion: () => false`. `vi.mock` is file-scoped, which is precisely why D-08 gets its own test file rather than another `describe` block in the isolation file.

**Do not use bare `act(() => useUiStore.getState().beginAnimation())` as the sole mid-deal setup.** A manual arm has no owning registration, so no unmount cleanup will ever release it and the counter would legitimately stay above 0 — such a test would either be wrong or would force a forbidden production `resetAnimations()` call. `05-PATTERNS.md` flags this exact trap.
