## Phase Goal

ROADMAP Phase 4 goal (engine/store-only, no user-visible surface): *"The deck/shoe model correctly represents 1 or 2 physical decks — two copies of the same card are distinct, trackable objects that never collapse via value-based dedup — and the simulation streaming pipeline is generalized to serve any game, with zero behavioral drift from v1.0 at deckCount=1."*

<mvp_note>
This phase is the sanctioned engine-foundation exception to MVP vertical-slice decomposition, matching the v1 precedents 01-01 (engine + RNG before any odds UI) and 02-01 (conditioning engine before street navigation UI). 04-CONTEXT.md's `<domain>` states it explicitly: "Engine/store-only: no new user-visible surface this phase (deck toggle UI is Phase 8; 2-deck gameplay is Phases 6-7)."

This plan in particular ships **zero production code** — it is a pure measurement instrument. Its user-facing value is negative-risk: it is the only thing standing between the user and a silent odds regression introduced by the refactor that follows. Roadmap success criterion 1 ("byte-identical to shipped v1.0") is unfalsifiable without it, which is why D-08 requires it to land first.

Note for the operator: ROADMAP's Phase 4 `**Goal:**` line is not in `As a / I want to / so that` form. That is consistent with the engine-foundation exception, but if a user-story-shaped goal is wanted, run `/gsd mvp-phase 4` before Phase 5.
</mvp_note>

<objective>
Record a seeded, literal-valued golden parity baseline captured from the CURRENTLY SHIPPED code, at both the engine layer and the worker-streaming layer, before a single line of the multiset/runner refactor is written.

Purpose: D-08's golden-first ordering. Roadmap criterion 1 demands proof that `deckCount=1` behaviour is byte-identical to shipped v1.0. The 216-test suite proves *shape* invariants (lengths, sums, uniqueness) but pins no *exact seeded values* — a count-aware `shoeWithout` that reorders `remainingDeck` by one position, or a runner extraction that consumes one extra RNG value, would pass all 216 tests while silently changing every reported probability. This plan closes that gap while the pre-refactor code is still the only code that exists.

Output: two additive test files holding hardcoded expected values transcribed from a real run of today's `master`. Nothing else in the repo changes.
</objective>
