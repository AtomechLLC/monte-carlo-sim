## Phase Goal

ROADMAP Phase 4 goal (engine/store-only, no user-visible surface): *"The deck/shoe model correctly represents 1 or 2 physical decks — two copies of the same card are distinct, trackable objects that never collapse via value-based dedup — and the simulation streaming pipeline is generalized to serve any game, with zero behavioral drift from v1.0 at deckCount=1."*

<mvp_note>
Contract-only plan, sanctioned engine-foundation exception (see 04-01's `<mvp_note>`). This is the first plan that touches shipped production behaviour, and it is deliberately shaped so the user-visible behaviour change is exactly zero: `deckCount` defaults to 1 everywhere, and 04-01's goldens are the acceptance gate. The user-visible payoff lands in Phase 6/7/8, which consume `ConditionedState.deckCount`.
</mvp_note>

<objective>
Thread `deckCount` through the conditioning layer and route `remainingDeck` derivation through the shared count-aware `shoeWithout`, then add the additive 2-deck property tests that DECK-01 and DECK-03 are verified by.

Purpose: `deriveConditionedState` is v1's second, independent copy of the Set-based collapse bug (ARCHITECTURE.md §(c) point 2 flags this explicitly as a DRY opportunity, not just a bug fix). Fixing it in place through the one helper means the phase ends with exactly one implementation of card-count math. DECK-03's without-replacement mandate then gets a permanent guard so a future contributor cannot reintroduce an "infinite shoe" shortcut and silently erase the whole deck-count feature (PITFALLS Pitfall 1).

Output: an optional `deckCount` on `ConditionedState`, a count-aware `deriveConditionedState`, and one new additive property-test file — with `equity.property.test.ts`'s 1-deck "13 unique cards" property untouched.
</objective>
