## Phase Goal

ROADMAP Phase 4 goal (engine/store-only, no user-visible surface): *"The deck/shoe model correctly represents 1 or 2 physical decks — two copies of the same card are distinct, trackable objects that never collapse via value-based dedup — and the simulation streaming pipeline is generalized to serve any game, with zero behavioral drift from v1.0 at deckCount=1."*

<mvp_note>
Contract-only plan, sanctioned engine-foundation exception (see 04-01's `<mvp_note>`). DECK-04's user-visible half — a picker that shows "1 of 2 remaining" and lets a user pick the same card twice — is Phase 7/8 scope by explicit decision (D-09: "no new visible UI this phase"; PITFALLS Pitfall 13 assigns the copy-count affordance to the UI/Picker phase). What lands here is the store-level count model and the selector that phase will render, delivered behind an unchanged 1-deck surface. Roadmap criterion 3 is worded to match: blocking is "verified count-aware ... with remaining-copy state exposed for the UI to consume."
</mvp_note>

<objective>
Make the card picker's duplicate blocking count-aware at the store level and expose per-card remaining-copy state, while leaving the rendered picker byte-for-byte identical at `deckCount=1`.

Purpose: DECK-04 and roadmap criterion 3. `pickerStore.setPick`'s `heldByAnotherSlot` boolean and `CardPicker`'s `new Set(pickedCards(picks))` are the last two value-collapse sites outside the simulation path (ARCHITECTURE.md §(c) point 4, PITFALLS Pitfall 6's fourth bullet). Converting them now — before Phase 7 needs a 104-card picker — means the 2-deck picker phase is a rendering change, not a correctness change.

Output: `remainingCopies` exported from `pickerStore.ts`, a count threshold in `setPick`, `CardPicker`'s disabled derivation driven by the same selector, and an additive `deckCount=2` describe block inside the existing test suite.
</objective>

<critical_constraint>
`deckCount` is a DEFAULTED PARAMETER, not a new store field.
